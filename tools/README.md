# tools/: where each claim this folder makes would break

One line per claim, the command that fails if the claim is false, and how to break it on purpose. Every command runs offline from the repository root, standard library only. "The checker" is `python3 tools/check_audit.py`; it names the check, the file and the line when it fails.

`python3 tools/sabotage_check.py` applies every sabotage below to a fresh scratch copy of the repository, one at a time, and requires the named command to fail there; it writes what it saw to `tools/SABOTAGE-PROOF.md` — **which means it leaves the working tree dirty**, so run it *before* `prove_order.py`, never after: `prove_order.py` checks that the tree is clean and will report the dirt this script just made. The order that produces two green files is sabotage first, commit, push, order proof last. The file it writes is the dated trace, so "it was tested" is something a stranger can re-run rather than take on trust.

- **"Every quote in every report is the standard's text, word for word."** The checker, C1: every `trecho citado` (quoted excerpt) cell in `examples.md`, `expected/*.md` and the round transcripts must be a substring of a file under `reference/pt/` (Portuguese row) or `reference/en/` (English row). Change one word inside a quote in `expected/nfse-01.md` and run it. `python3 tools/check_audit.py --selftest` runs the same check on `tools/selftest/bad-report.md` and must fail there.
- **"The excerpts are cut from the full texts, not retyped."** The checker, C0: every file in `reference/pt/excerpts/` is a substring of a file in `reference/pt/full/`; same for `en/`. Change a byte in any excerpt and run it; `--selftest` plants one and must catch it.
- **"Every fixture has a prediction, and every mutation names the check that must catch it."** The checker, C3: one `expected/` file per XML in `fixtures/`; each `fixtures/mutations/<slug>/CHANGE.md` names the field and the rule, and the prediction FAILS on that check. Delete `expected/m2-campo-obrigatorio.md`, or turn its FALHA (fail) into PASSA (pass), and run it.
- **"The same violation is caught under three wordings."** `fixtures/rephrase/` holds the wrong service code of `m1` with the description reworded three ways, each with its prediction (`ls fixtures/rephrase/*.xml expected/m1-rephrase-*.md`); the checker's C3 covers them. The three runs, one conversation each, are examples 5 to 7 of `rounds/fixture-runs-v1/report-all-runs.md` (check `1-código`, the service code, FALHA on all three). What the command proves is that the fixtures and the predictions exist; that the auditor catches it is the author's recorded run, on the author's own note; re-run it to check.
- **"What the operator loads is what the README says, and never the evidence."** The checker, C5: the load list in `README.md` and in `CLAUDE.md` must name the auditor's files and never `fixtures/`, `expected/`, `rounds/`, `tools/` or the full texts; `CLAUDE.md` is at most twelve lines and holds no rule. Add `fixtures/` to the load line of the README, or the word `PASSA` to `CLAUDE.md`, and run it. `python3 tools/make_load_folder.py <dir>` builds the operator's folder from the same rule and refuses a path under any never-load folder: add `fixtures/clean/nfse-01.xml` to its `LOAD` list and run it.
- **"The zip the operator downloads is these files, as they are now."** `python3 tools/make_load_folder.py --check`: the committed `download/nfse-auditor-carregar.zip` must hold exactly the files the load list names, byte for byte; a file edited after the last build fails it. Add a character to `identity.md` and run it; `python3 tools/make_load_folder.py download` rebuilds.
- **"No real identifier anywhere."** The checker, C6: it fails on any file that holds a check-digit-valid CNPJ or CPF outside the anonymiser's synthetic ones, an e-mail that is neither `noreply` nor a `.invalid` placeholder, or a certificate block. Paste a valid CNPJ or CPF into any `.md` and run it. **It does not check phone numbers**: this sentence promised one until 11/09/2026, and the CPF half was promised without being wired — the function existed and was never called. Both were found by a cold audit and are written here rather than quietly fixed, because this file's whole job is to say what the commands do and not what they were meant to do. Names are checked against a private list (`--names <file>`, kept outside the repository), so that check cannot be run by a stranger; what the anonymiser replaces and what it keeps is the table in `fixtures/README.md`.
- **"Predictions were committed before reports, and the public remote is this history."** `python3 tools/prove_order.py --verify` reads git (never file times): for every round and control, `expected.md` was first committed before `transcript.md`, round N before N+1, and a fresh clone of the remote reproduces the same order and passes the checker. In a new `rounds/round-N-*/` folder, commit `transcript.md` before `expected.md` and run it. The output of the last full run is `rounds/ORDER-PROOF.md`.
- **"The checker is not decoration."** `python3 tools/check_audit.py --selftest`: `tools/selftest/bad-report.md` must fail on named checks and `good-report.md` must pass. Fix the bad report and the selftest fails.
